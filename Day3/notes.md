# 📘 Day 3 – JDK, JRE, JVM & JVM Architecture

## 1. JDK (Java Development Kit)
JDK is the complete toolkit required for developing Java applications.

### JDK Includes:
- **JRE (Java Runtime Environment)**
- **Development Tools** (javac, jdb, javadoc, etc.)

### Purpose:
- To **write**, **compile**, and **run** Java programs.

### Flow for Developers:
1. Write code  
2. Compile using ``  
3. Run using `java`

---

## 2. JRE (Java Runtime Environment)
JRE is required to **run** Java programs but **cannot compile** them.

### JRE Includes:
- **JVM (Java Virtual Machine)**
- **Runtime Libraries** (Java predefined class files)

### Purpose:
- Used by **clients/users** who only need to run `.class` files, not develop programs.

---

## 3. JVM (Java Virtual Machine)
JVM is responsible for **executing Java bytecode**.

### JVM Responsibilities:
- Loading class files  
- Verification & security checks  
- Memory management  
- Execution of bytecode  
- Garbage collection  

### Key Point:
Each Operating System has its **own JVM**, which makes Java platform-independent.

---

# 🧠 JVM Architecture

## 1. CLSS (Class Loader Subsystem)
Class Loader loads the `.class` files into memory.

### It Performs:
- **Loading**
- **Verification** (checking bytecode validity & security)
- **Linking**
- **Initialization**

### Summary:
“Give me the class file — I’ll load it, verify it, link it, and prepare it for execution.” 🔍

---

## 2. JVM Memory Areas

### 🧩 Method Area
- Stores **static variables**
- Stores **class-level metadata**  
  (class name, package, parent class details)

### 📦 Heap
- Stores **objects**
- Stores **instance variables**

### 🥞 Stack
- Stores **local variables**
- Stores **method calls**
- Stores **temporary data**  
  (memory cleared after method execution)

### 🎯 Program Counter (PC Register)
- Stores the **address of the current instruction**
- Prepares the address of the **next instruction**  
- Acts like the “GPS of your code”

### 🧬 Native Method Stack
- Stores native (non-Java) method information  
- Used for C/C++ calls through JNI (e.g., JDBC drivers)

---

## 3. Execution Engine
Executes the bytecode generated by the compiler.

### Components:

### ✔ Interpreter
- Executes code **line-by-line**
- Slower but useful for initial execution

### ✔ JIT Compiler (Just-In-Time)
- Identifies repeated bytecode  
- Converts it to fast machine code
- Improves performance significantly

### ✔ Garbage Collector
- Removes unused objects automatically
- Frees heap memory

### Summary:
The Execution Engine is fast, intelligent, and cleans up automatically.

---

# 🔄 Execution Flow Summary
1. Java source code (`.java`)  
2. Compiled to bytecode by `javac` → `.class`  
3. JVM loads the `.class` file via Class Loader  
4. Bytecode checked & linked  
5. Execution Engine interprets/JIT compiles  
6. Garbage Collector manages memory  

---

# 📌 Key Takeaways from Day 3
- JDK = JRE + Development Tools  
- JRE = JVM + Libraries  
- JVM runs bytecode and manages memory  
- JVM Architecture includes CLSS, Memory Areas, Execution Engine  
- Java is **compiled + interpreted**  
- Memory is divided into Method Area, Heap, Stack, PC, and Native Method Stack  
- JIT improves Java execution speed  
- Garbage Collector handles memory cleanup
